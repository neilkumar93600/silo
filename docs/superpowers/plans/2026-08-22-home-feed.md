# Home Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix Home showing only root-folder files, and turn Home's Files section into a merged feed of the user's own files (any folder) plus files shared with them, ordered by most recent activity (upload, share, or last time it was opened) — plus guarantee a 2-column grid on mobile.

**Architecture:** A new `file_views` table tracks the last time each user opened each file (own or shared), upserted from the single existing chokepoint both preview and download already call (`filesService.getDownloadUrl`). A new `getHomeFeed` service merges owned files + shared-with-me files + view timestamps in application code (not a SQL UNION), computes each file's most recent activity timestamp, and returns the top 50. The frontend gets a new `FileManager` mode (`"home"`) that fetches this feed alongside the existing root-folder shortcuts, and `FileGrid`/`FileTable` gain per-row (not per-page) read-only enforcement so shared files sit safely alongside owned ones in the same grid.

**Tech Stack:** Express + Drizzle ORM + Postgres (api/), Next.js + React (web/), Vitest (api/ only — web/ has no test harness, verified manually via `npm run typecheck` + dev server).

**Spec:** [docs/superpowers/specs/2026-08-22-home-feed-design.md](../specs/2026-08-22-home-feed-design.md)

## Global Constraints

- Home's merged feed is capped at 50 items, no pagination UI — matches the existing app-wide pattern (Recent page already caps at 50 with no "load more" anywhere).
- View tracking never fires for anonymous public share-link (`/s/[slug]`) access — only authenticated owner/shared-recipient views count.
- `file_views` is one row per `(userId, fileId)`, upserted — not an append-only log.
- Shared files are always read-only wherever they appear alongside owned files in one list — enforced per-row via the existing `sharedBy` field and `readOnly` prop, not a new prop.
- Follow existing patterns exactly: service functions take `(fileId, userId, ...)` or `(userId, ...)`, routes are thin (`try { res.json(await service.fn(...)) } catch (err) { next(err) }`), tests mock `db` via the `chainable()` proxy helper already used in `api/tests/*.test.ts`.

import { pgTable, text, timestamp, uniqueIndex, index } from "drizzle-orm/pg-core";
import { user } from "./auth.js";
import { files } from "./files.js";

// One row per (user, file) — upserted on every view, not an append-only
// log. Only the latest viewedAt is ever read.
export const fileViews = pgTable(
  "file_views",
  {
    id: text("id").primaryKey(),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    fileId: text("file_id")
      .notNull()
      .references(() => files.id, { onDelete: "cascade" }),
    viewedAt: timestamp("viewed_at").notNull().defaultNow(),
  },
  (table) => [
    uniqueIndex("file_views_user_file_idx").on(table.userId, table.fileId),
    index("file_views_user_id_idx").on(table.userId),
  ],
);

Create `api/src/services/home.service.ts`:

```ts
import { and, desc, eq, inArray, isNull } from "drizzle-orm";
import { db } from "../db/index.js";
import { files } from "../db/schema/files.js";
import { fileViews } from "../db/schema/file-views.js";
import { listSharedWithMe } from "./shares.service.js";

// Matches the app's existing no-pagination pattern — /dashboard/recent
// already caps at 50 with no "load more" UI anywhere.
const HOME_FEED_LIMIT = 50;

export async function getHomeFeed(userId: string) {
  const [ownedFiles, shared] = await Promise.all([
    db
      .select()
      .from(files)
      .where(and(eq(files.ownerId, userId), eq(files.status, "uploaded"), isNull(files.deletedAt)))
      .orderBy(desc(files.createdAt))
      .limit(HOME_FEED_LIMIT),
    listSharedWithMe(userId),
  ]);

  // A file shared with your own email (edge case) shows up in both sets —
  // keep the owned copy only.
  const sharedFiles = shared.files.filter((f) => f.ownerId !== userId);

  const allIds = [...ownedFiles.map((f) => f.id), ...sharedFiles.map((f) => f.id)];
  const viewRows = allIds.length
    ? await db
        .select()
        .from(fileViews)
        .where(and(eq(fileViews.userId, userId), inArray(fileViews.fileId, allIds)))
    : [];
  const viewedAt = new Map(viewRows.map((v) => [v.fileId, v.viewedAt.getTime()]));

  const withActivity = [
    ...ownedFiles.map((f) => ({
      file: f,
      lastActivityAt: Math.max(f.createdAt.getTime(), viewedAt.get(f.id) ?? 0),
    })),
    ...sharedFiles.map((f) => ({
      file: f,
      lastActivityAt: Math.max(new Date(f.sharedAt).getTime(), viewedAt.get(f.id) ?? 0),
    })),
  ];

  withActivity.sort((a, b) => b.lastActivityAt - a.lastActivityAt);

  return { files: withActivity.slice(0, HOME_FEED_LIMIT).map((entry) => entry.file) };
}
```
